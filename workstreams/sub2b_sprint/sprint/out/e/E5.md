# E5 — one QAIRT pin and an honest artifact registry

## Outcome

Lane E pins both compilation and device runtime to **QAIRT/QNN `2.45.0.260326154327`**, with exact string equality required. Older, newer, or unknown context builds are rejected before load. No compatibility assumption can override that rule.

The official `v2.45.0.260326.zip` archive was downloaded once, verified at **1,657,471,677 bytes** with SHA-256 **`aff2f154319d88db81a4125c35882395cd88c024959ca3cc3cda3ba442ef2df0`**, and deleted after extraction. All 11 allowlisted runtime, identity, licence and notice members match the prior expected sizes and hashes and are staged locally under `artifacts/nubia_bundle/runtimes/qairt-2.45.0.260326154327/`.

This does **not** make the NPU bundle runnable. There is no exact-2.45 app-UID runner, and zero staged QNN contexts match the pin.

## Why 2.45

| Candidate | Decision | Binding evidence |
|---|---|---|
| QNN `2.40.0.251030114326_189385` | Reject as programme pin | E3's three genuine SM8850 Parakeet contexts embed this exact build. They are REPACKAGE-safe only in an exact-2.40 process, which would conflict with the programme's 2.45 Qualcomm/GenieX assets. |
| QAIRT `2.45.0.260326154327` | **Select** | Four authenticated SM8850 Supertonic contexts, E4's SM8850 Qualcomm registry rows, Qwen3-0.6B GenieX-QAIRT metadata, and GenieX v0.3.18's embedded QNN libraries all identify this build. The matching Android runtime supply is now locally verified. |
| QAIRT `2.47.0.260601114230` | Reject | E1 listed it, but Lane E has no accepted SM8850 context set or pinned application runtime at this exact build. |
| QAIRT `2.48.0.260626120635` | Reject | E1's 2.48 compile succeeded on SM8750, not SM8850. This account cannot select SM8850, and 2.48 would mismatch every existing 2.45 and staged 2.40 context. |

The sprint's exact-match safety rule is stricter than any general claim of runtime backward compatibility: **compile build must equal device build** for every NPU context shipped by this lane.

## Registry state

`artifact_registry.json` contains 36 rows with source URL, immutable revision where known, bytes, published/local checksum, licence, destination, type, required runtime, readiness and blocker.

- The staged Parakeet archive contents are fully hashed. Its three context binaries target SM8850/HTP v81 but embed QNN 2.40, so they are retained as evidence and are **execution-blocked** until recompiled at exact 2.45.
- The pinned CPU ONNX reference has exact revision, bytes and locally computed hashes. It was deleted after the E3 reference run and is reproducible; it is not part of the device bundle.
- The exact 2.45 raw QAIRT runtime provider is staged and hash-verified. Qualcomm object-code terms still constrain distribution to incorporation in the application.
- Qualcomm GenieX Android AAR v0.3.18 is a valid mutually exclusive alternative: tag commit `71fa27123de979fe484fa9355c3587afc2cd3f76`, 81,249,217 bytes, upstream-published SHA-256 `5df6803e5c750e903769dc991be654c0b6af0a0f2311471c5721b6818855612e`, embedded QAIRT 2.45. It was not downloaded or integrated. If selected, the raw QAIRT set must be removed from that APK/process.
- The four existing Supertonic contexts match 2.45 but remain blocked until authenticated download and external SHA-256 pinning.
- Qwen3-0.6B's SM8850 w4a16 package is not accepted: bytes/hash are unknown and Qualcomm disables the path after an accuracy failure.
- Qwen3.5-0.8B's E4 GGUF URL still points at moving `main`; exact revision, bytes, checksum, licence and runner are unresolved dependencies.
- The application runner is **MISSING**. Artifacts selected by lanes A-D for the complete five-language stack remain an explicit `UNKNOWN` dependency rather than invented registry entries.

## Stop conditions

NPU execution must stop unless all of these are true:

1. Every context records exact compile build `2.45.0.260326154327`.
2. Exactly one QNN runtime provider is packaged: the staged raw QAIRT set **or** GenieX AAR, never both.
3. Every executable, library, model and context has an immutable revision, exact bytes, SHA-256 and resolved licence.
4. An app-UID runner enforces those checks without silent CPU fallback.

Today conditions 1 and 4 fail. Therefore the honest current capability is **verified staging only; no phone NPU execution authorized**.

## Limitations

No phone was connected or changed. The E1 account cannot compile for SM8850, so the Parakeet recompile is blocked. The registry is complete for Lane E's identified artifacts, not for the final five-language product; that requires the immutable manifests from lanes A-D.
