# E6 — staged Nubia bundle

## Outcome

Lane E staged a fail-closed Nubia NX809J bundle at `artifacts/nubia_bundle/`, but it is **not executable today**: `BLOCKED_APP_RUNNER_MISSING` and `CPU_STAGE_ONLY`. No phone was connected, queried or mutated. Large model, audio and Qualcomm runtime payloads remain git-ignored; the small scripts, manifests and safety markers are committed as the reproducible control plane.

The one programme QAIRT pin is exact **`2.45.0.260326154327`**. Eleven members extracted from the official QAIRT archive are locally staged and hash-verified (125,314,830 bytes selected from the verified 1,657,471,677-byte archive, SHA-256 `aff2f154319d88db81a4125c35882395cd88c024959ca3cc3cda3ba442ef2df0`). Qualcomm runtime object code remains subject to incorporation into the authorized app; the engineering `qnn-net-run` binary is never shell-executed by these scripts.

The three useful SM8850 Parakeet contexts are also staged and verified, but their headers say exact QNN **`2.40.0.251030114326_189385`**. They are registered `REFERENCE_ONLY_NPU_BLOCKED`, excluded from installation, and may never be loaded with the 2.45 runtime. Zero exact context/runtime pairs are enabled.

## Scripts and safeguards

`install.sh`, `verify.sh`, `run.sh` and `collect.sh` use POSIX shell plus `adb`/Android toybox. They require exactly one authorized NX809J/SM8850 arm64 device, reject every adb forward, verify byte sizes and SHA-256 values, and require `run-as` UID to equal the package UID. Inference launches only through the configured Android Activity; no shell-owned runner is permitted.

NPU selection requires exact equality among the pin, every context compile build and the installed runtime identity. The installed five-member HTP runtime and every enabled context are hashed again from their final app-owned locations. Direct NPU requests fail rather than fall back. CPU requests require the app to report no QNN versions, while NPU requests require `cpu_fallback=0` and exact compile/runtime identities. Known mismatch log signatures invalidate the session.

`PHONE_RUNBOOK.md` records the future sequence: identity → bundle hash verification → APK/app-private install → installed verification → airplane-mode app-UID run → evidence collection. It states the current blocker before the commands so the first phone session cannot accidentally convert staging into a false execution claim.

## Validation

- `bash -n`: passed for all operational and mock scripts.
- `shellcheck -x -s sh`: passed cleanly for all operational, shared and mock scripts.
- Mocked `adb`, never a real device: seven safety cases passed—missing APK stops before adb, direct NPU stops on 2.40/2.45 mismatch, zero devices rejected, non-SM8850 rejected, one NX809J/SM8850 arm64 accepted, any adb forward rejected, and an unreadable forward-list state rejected rather than treated as safe.
- Phone calls / pushes / installs / executions during E6: **0**.

## Remaining blockers

1. No APK implements the app-private import/request/result contract.
2. No complete CPU five-language stack is staged from lanes A–D.
3. No staged QNN context matches exact QAIRT 2.45; Parakeet requires a fresh SM8850 compile, currently blocked by E1 account target selection.
4. Sample-audio redistribution rights are unresolved; fixtures remain ignored and internal-test-only.

Therefore E6 delivers a verified offline staging bundle and a mechanically guarded phone procedure, not a phone result or runnable NPU stack.
