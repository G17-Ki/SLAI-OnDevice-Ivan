## The hidden-dependency sweep — what vendors omit

I diffed the HF API total against the full recursive file tree for every repo, then read
the configs for external checkpoint references. Four things fell out.

### 1. Magpie ships no codec. Stack L is missing a row. ← the significant one

`nvidia/magpie_tts_multilingual_357m` totals 359,698,319 (`EXACT`, bound held). But its
`model_config.yaml`, extracted from inside the `.nemo`, declares:

```
codecmodel_path: nvidia/nemo-nano-codec-22khz-1.89kbps-21.5fps
```

The checkpoint contains sixteen codebook embedding tables
(`audio_embeddings.{0..15}.weight`, each `[2024, 768]`) and a
`local_transformer_out_projections` — it *emits* 16-codebook audio tokens. There is no
decoder in it that turns those tokens into a waveform. **Magpie cannot produce audio
without a separate checkpoint that was never in the ledger.**

§2.2 flagged exactly this risk — *"If the codec ships as a separate checkpoint it is a
separate row — verify at T011"*. It is a separate row.

I parsed it:

| nemo-nano-codec-22khz | params |
|---|---:|
| `audio_decoder` | 31,581,690 |
| `audio_encoder` | 31,019,224 |
| `vector_quantizer` | 64 |
| **inference path** | **62,600,978** |
| `discriminator` | 43,372,800 |
| `mel_loss_fn` + `stft_loss_fn` | 113,547 |
| full `.nemo` checkpoint | 106,087,325 |

Ledgered at **62,600,978** — the inference path. The 43,486,347 of GAN discriminator and
loss modules are training-only and never ship; I record 106,087,325 as `ub_worst_case` in
case the export is not pruned. If reference-audio voice cloning is dropped, the encoder
goes too and the row falls to 31,581,754.

L absorbs it: headroom 323,266,106 → still comfortable. But it was invisible, and it is
the difference between a ledger that is right and a ledger that is lucky.

### 2. Qwen3.5-0.8B carries a vision tower in the same safetensors file

`Qwen/Qwen3.5-0.8B` reports 873,438,784 from the API. The subtree split:

| subtree | params |
|---|---:|
| `model.language_model` | **752,393,024** |
| `model.visual` | 100,592,896 |
| `mtp` | **20,452,864** |

The LM and MTP figures confirm §2.2/§2.3 **to the parameter**. But §2.2 says the vision
tower "ships separately (`mmproj-*.gguf`) and is not shipped" — that is true of the
*GGUF* artefact, not of the upstream repo, where all three live in one file.

The exclusion is legitimate under B-2 **only because the shipped artefact is the LM-only
GGUF**. That is now a build-time assertion, not an assumption: any build that ships the
upstream safetensors takes **+100,592,896**, which Stack D (headroom 168,466,775) would
feel immediately. Carried in `ledger.json` as a NOT-COUNTED row so it cannot be forgotten.

### 3. The zh-en Zipformer's "69,880,000" was not a bound

`pfluo/k2fsa-zipformer-chinese-english-mixed` — the shipped ONNX set:

| graph | params |
|---|---:|
| encoder | 67,076,859 |
| decoder | 3,468,801 |
| joiner | 3,208,302 |
| **total** | **73,753,962** |

**3,873,962 above** the ledgered 69,880,000. That figure was a community round number
described as `UB`; it was not conservative. Affects H2 and L2. The repo also contains
`exp/rnn-lm-small-text-19.pt` (11,400,010 params) — an optional LM-rescoring model that
costs nothing unless a build enables it; recorded so nobody enables it silently. The
training checkpoint `exp/pretrained.pt` totals 75,528,536, the extra being pruned-RNN-T
projections that are not exported.

### 4. Supertonic-3 ships ten voice styles, not five

`voice_styles/` contains **F1–F5 and M1–M5**. Each is
`style_ttl [1,50,256]` + `style_dp [1,8,16]` = **12,928** — the per-style figure in §2.3
was exactly right; the count of styles was not. The row is **129,280**, not 64,640.

§2.3 records a "Supertonic correction" that added the 64,640 and registers the superseded
total as a banned string. That correction was half-done. Shipping five styles is a
different, smaller ledger under L-2 — but the repo ships ten.

## Bounds that were breached

Three "conservative" figures were not conservative. All three are small; all three matter
because a bound that fails upward is the one mechanism by which a conservative ledger
stops being conservative (§Q-4).

| row | prior | measured | over by |
|---|---:|---:|---:|
| k2fsa-zipformer zh-en | 69,880,000 `UB` | **73,753,962** | +3,873,962 |
| canary-180m-flash | 182,000,000 `UB` | **183,743,137** | +1,743,137 |
| RU Zipformer INT8 (D3) | 65,000,000 `UB` | **65,610,041** | +610,041 |

canary's bound was "a vendor round figure above the *180m* name" — the name was not an
upper bound on the count. The RU Zipformer figure is confirmed twice: the int8 artefact
measures 65,610,041 and its float twin 65,609,459, which also demonstrates **Q-1
precision-invariance** to within 582 export-only tensors.

## The one genuinely unpublished row, closed

**Silero `v5_cis_base` (L6) = 22,850,584 `EXACT`.** §2.2 called this "genuinely
UNPUBLISHED" with a `≤100,000,000` bound and made it L's #1 headroom reservation, noting
L survives any value below 409,875,339.

The artefact is a `torch.package` archive on `models.silero.ai`, whose server ignores
Range requests — so this is the single 91,680,514 B download in the lane, parsed and
deleted. I walked it with a stubbed meta-unpickler (no packaged code executed): 317 unique
storages, all fp32, reconciling to storage bytes 91,402,340 / 4 = 22,850,585 (Δ1 is a
view). It ships 60 speaker embeddings.

**77,149,416 below its bound**, and the largest single correction in the lane.

It also **refutes** the premise behind that bound. §2.2 says the bound is 100,000,000
rather than 20,000,000 because a stress marker (`silero_stress`) is *bundled inside*. It
is not: the module's constructor takes `accentor=None`, and no accentor tensors exist in
the archive. L therefore needs an **external** RU stress row — see A5, row L9.

## Stack M

Every row confirms or improves on the prior. M1 is settled by A1 at **782,426,112**
(TIED). M3 MOSS-TTS-Nano is **117,311,232** (bf16, tensor-level) against a prior of
117,346,547 that was `floor(bytes/2)` labelled `EXACT`.

MOSS's ONNX export is the S-4 trap §1.3 warned about, and worse than recorded. Enumerating
all five graphs and de-duplicating by external-data `(location, offset, length)`:

- naive per-graph sum: **391,092,480** — a 3.3× trap
- unique by offset: **167,622,912** (= 670,491,648 B / 4, fp32)
- true model: **117,311,232**

The excess is the 16384×768 audio embedding materialised **three times**:
`core.model.transformer.wte.weight` (global), `model.transformer.wte.weight` (local), and
`onnx::MatMul_5889` — the transposed output head. Ledgered at 117,311,232 under S-2, with
167,622,912 carried as `ub_worst_case`.

## What I could not close

- **M7 / D11b — ASR-side punctuation and ITN.** `UNKNOWN`, never interpolated. A5 sizes

  carry punctuation for es/fr/ru, and does Qwen3-ASR emit it. Both are ~20-minute checks.
- **The nemo-nano-codec export.** I ledger the inference path; whether the shipped export
  prunes the discriminator is unverified. Worst case +43,486,347, which L absorbs.
- **RU Zipformer identity.** I measured the public `sherpa-onnx-zipformer-ru-int8-2025-04-20`,
  which matches the in-project artefact's date and archive size (60.2 MB). The in-project
  binary itself was not available to hash. If they differ, the row moves.
