# A2 — Parakeet-tdt-0.6b-v3: 627,057,310 or 627,057,286?

**Both. They are the same file counted on two different bases, and the Δ24 is now named:
24 scalar I64 BatchNorm step counters.** `EXACT`.

## The 24

`nvidia/parakeet-tdt-0.6b-v3`, `model.safetensors`, 723 tensors, header parsed over
HTTP Range. Partitioned by dtype:

| dtype | params |
|---|---:|
| F32 | 627,057,286 |
| I64 | 24 |
| **total** | **627,057,310** |

There are exactly 24 non-F32 tensors in the file, and all 24 are:

```
encoder.layers.{0..23}.conv.norm.num_batches_tracked   I64  shape []  = 1 each
```

One scalar per encoder layer, 24 encoder layers, 24 scalars. These are torch BatchNorm
`num_batches_tracked` buffers — an integer incremented once per training batch. Nothing
is left unexplained; the residual is fully accounted.

## Which one belongs in the ledger

**627,057,286.** `§1.2` excludes "I64 index/shape buffers and constant tensors that carry
no learned value". A BatchNorm batch counter carries no learned value and is never read
at inference.

`01_STACK_DECISION.md` counts 627,057,310 as the conservative figure. Keeping it costs
24 parameters against a 2,000,000,000 cap and changes nothing. Either is defensible —
the point of A2 is that the delta is now *closed* rather than *open*.

## A finding I did not go looking for

I cross-checked against the `.nemo` (TAR walk → `model_weights.ckpt` → ZIP central
directory → `data.pkl` meta-unpickle, no weights read). It totals **622,165,166** —
**4,892,144 fewer** than the safetensors.

| module | .nemo | safetensors | Δ |
|---|---:|---:|---:|
| encoder | 608,928,792 | 608,928,792 | **0** |
| decoder | 11,807,360 | 12,217,600 | +410,240 |
| joint | 6,321,158 | 5,254,918 | −1,066,240 |
| encoder_projector | 0 | 656,000 | +656,000 |
| preprocessor | 33,296 | 0 | −33,296 |

The encoder — 97.1% of the model — matches exactly. All the divergence is in the
decoder/joint/projector head, which the HF-transformers repackaging restructures, plus a
`preprocessor` block (mel filterbank + STFT window) that the `.nemo` carries as a module
buffer and the safetensors export drops. That block is non-learned DSP constant data and
would not count under `§1.2` in any case.

**The safetensors export is the shipped basis** (the sherpa-onnx and QNN exports derive
from it), so 627,057,286 / 627,057,310 stands.

Worth recording anyway: **two packagings of the same checkpoint differ by 4,892,144
parameters in their head modules.** Any future audit that mixes a `.nemo`-derived figure
with a safetensors-derived figure for parakeet will be wrong by that amount. Better a
noted fact than a rediscovered surprise.
