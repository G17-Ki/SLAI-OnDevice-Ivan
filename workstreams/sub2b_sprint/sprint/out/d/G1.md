## ONNX tied-table trap

I enumerated all five split TTS graphs and keyed external tensors by location, offset, and length:

| Count basis | TTS elements |
|---|---:|
| Naive sum across every graph | 391,092,480 [EXACT] |
| Unique external-data offsets, 670,491,648 FP32 bytes | 167,622,912 [EXACT] |
| True unique PyTorch storages | 117,311,232 [EXACT] |

The naive figure is 3.333803 times the true model [PROJECTED]. The 16,384 × 768 text table appears at three physical external-data segments: the global embedding, the local embedding, and the transposed local output head.

The lane's specific audio-codebook question is independently answered by the 1,024 × 768 tables:

| Physical FP32 materialization | Groups | Bytes |
|---|---:|---:|
| Global `core.model.audio_embeddings.{0..15}.weight` | 16 | 50,331,648 [EXACT] |
| Local `model.audio_embeddings.{0..15}.weight` | 16 | 50,331,648 [EXACT] |
| Transposed local output-head MatMul initializers | 16 | 50,331,648 [EXACT] |
| Physical total | 48 | **150,994,944 [EXACT]** |
| One logical copy | 16 | **50,331,648 [EXACT]** |
| Redundant materialization | 32 | **100,663,296 [EXACT]** |

This was enumerated across all five pinned protobufs by external-data file, offset, and length. Some split graphs list only local embeddings 0..14, but the cached-step graph contains and consumes `model.audio_embeddings.15.weight`; excluding it would undercount the shipped physical data. Thus both the tied text head and all 16 tied audio-codebook embedding/head groups cease to be one shared PyTorch storage in the export.

Lane A's A3 prose calls the 16,384 × 768 `wte`/head tensor an audio embedding. Its initializer names and the PyTorch state dict identify that tensor as the **text-token** embedding/head table. This is a role-label correction, not a count or conclusion change: Lane A's 117,311,232 adopted count and its warning about three-copy ONNX materialization remain correct, while the 1,024 × 768 audit above directly answers Lane G's audio-codebook question.

The two tied-table families contribute **50,331,648 gross duplicate FP32 elements [EXACT]**: 25,165,824 from the text table and 25,165,824 from the audio-codebook groups. That is 19,968 more than the export's **50,311,680 net unique-offset excess** over PyTorch. The export therefore omits, folds, or restructures 19,968 other elements (79,872 FP32 bytes); their exact tensor identity is `UNKNOWN`. Gross tied-table duplication must not be equated with the net export excess.

For the learned-parameter inventory, use **117,311,232**. If the official ONNX files are the shipped artifact, separately carry **167,622,912** as the conservative physical export basis. Never add initializers graph by graph.
