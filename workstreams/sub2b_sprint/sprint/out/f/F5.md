# F5 — Deployment delta: adding Spanish and French to the phone

This is a procedure. You should be able to execute it at the Nubia without opening
another document. Where it says a step of `docs/ANDROID_DEPLOYMENT.md` is unchanged, it
is unchanged and you run it exactly as written there.

Set this once:

```bash
export ESFR=workstreams/sub2b_sprint/sprint/out/f/artifacts/nubia_esfr_bundle
export SERIAL=YOUR_ADB_SERIAL
```

## 0. Two corrections before you start

**There is no 0.4.14 APK.** `android-app/releases/` contains exactly one retained
artifact: `lfm-audio-demo-0.4.13-expressive-lfm-debug.apk`, version code 21, 4,814,778
bytes, SHA-256 `b178c93f05d614f8156843755ea52697f55b299c5bb0b6812209d9ce5f139baf`. It
predates the runtime companion entirely and is **not** a fallback for the current
two-package deployment (`android-app/releases/README.md`, `docs/ANDROID_DEPLOYMENT.md:22`).
The real rollback is §6 and it is better than an APK swap.

**Spanish and French are CPU-only and slow.** Expect roughly **7–11 seconds** per ES/FR
recognition turn (`PROJECTED`; F2 §4). Most of that is ONNX Runtime re-creating a 652 MiB
session, because the companion spawns its recognizer per request. This is not a bug you
can fix at the phone tonight. Plan the shot list around it (§5).

## 2. Before you plug anything in


All five must pass. The first two never touch adb. If `install_esfr.sh --dry-run` reports

## 3. Step 4b — the ES/FR ASR overlay

Run steps 1–4 of `docs/ANDROID_DEPLOYMENT.md` first, including the Apps AI-control
provisioning and its reboot check. Then:

```bash
$ESFR/install_esfr.sh
```

It refuses to proceed unless there is exactly one authorized adb target that is provably
NX809J / SM8850 / arm64-v8a, there are zero adb forwards, both packages are already
installed, and `run-as` resolves to the companion's own UID. It imports 16 files
(670,478,772 bytes of Parakeet plus 12 fixtures), hashes every one on the host and again
after import, and places each atomically. It installs no APK and clears no data.

```bash
$ESFR/verify_esfr.sh
```

This is the gate that matters. It opens a temporary loopback forward, posts the two ES/FR
fixtures, and requires:

- `backend == parakeet_v3_cpu` and `provider == cpu`;
- transcripts **exactly** equal to
  - es — `No preguntes qué puede hacer tu país por ti, pregunta qué puedes hacer tú por tu país.`
  - fr — `Ne vous demandez pas ce que votre pays peut faire pour vous. Demandez-vous plutôt ce que vous pouvez faire pour lui.`
- `parakeet_v3_cpu.execution_verified == true` and `runner_owned_by_service == true`;
- the accepted stack still `complete` — an overlay that breaks EN/ZH/JA/KO/RU is a failed
  overlay, not a partial success;

then removes the forward and proves none remains. It prints a round-trip time per
language: **write those two numbers down**, they are the first real phone measurement of
this route and they replace F2's projection.

## 4. Step 5 — the TTS catalog, metadata only

Spanish and French reuse the Supertonic graphs already on the phone. The `files` map in
the two new candidate rows is byte-identical to the shipped RU/JA/KO rows, so
`Candidate.sharesModelWith()` matches and no model file is added, moved, or reloaded.

Re-stage the catalog from the updated generator:

```bash
python3 scripts/tts_research_20260726/stage_device_bundle.py \
  --resident-manifest /path/to/current/tts-eval/bundle_manifest.json \
  --output-dir /tmp/tts-eval-esfr
```

Confirm the two rows are present and that no model file is being added:

```bash
python3 - <<'PY'
import json
c = json.load(open("/tmp/tts-eval-esfr/candidates.json"))["candidates"]
by_id = {x["id"]: x for x in c}
shared = {"supertonic3_s5", "supertonic3_ja_s5", "supertonic3_ko_s5",
          "supertonic3_es_s5", "supertonic3_fr_s5"}
assert shared <= set(by_id), sorted(shared - set(by_id))
files = {json.dumps(by_id[i]["files"], sort_keys=True) for i in shared}
assert len(files) == 1, "ES/FR must reuse the resident Supertonic graphs"
print("ok: 5 Supertonic language routes share 1 graph set; 0 new model bytes")
PY
```

Then push metadata only:

```bash
scripts/install_main_app_tts_bundle.sh --serial "$SERIAL" \
  --bundle /tmp/tts-eval-esfr --manifest-only
scripts/install_main_app_tts_bundle.sh --serial "$SERIAL" \
  --bundle /tmp/tts-eval-esfr --verify-only
```

`--manifest-only` verifies every resident asset, transfers zero model files, and installs
`candidates.json` last. `--verify-only` must then authenticate all assets and all three
metadata files with zero changes. If `--manifest-only` refuses, the resident assets do not
match — do **not** force it; fall back to a full `--bundle` push of the unchanged tree.

## 5. Step 7 — what "working" looks like, per language

Open **LFM Audio** on the phone (it starts the companion; there is no boot receiver).
Wait for the status line to leave "Starting model". Then run these turns from the phone UI.

| # | Language selector | Say | Working looks like | Expected wait |
|---|---|---|---|---|
| 1 | Auto | "What is the capital of France?" | SenseVoice **QNN** transcript → LFM expressive answer, English voice | ~1 s to first text |
| 2 | Chinese | 「北京在哪里？」 | Han transcript, Matcha Baker voice | ~1 s |
| 3 | Russian | «Расскажи коротко о Москве» | Cyrillic transcript, Supertonic RU voice | ~1–2 s |
| 4 | **Spanish (CPU)** | "¿Cuál es la capital de España?" | Accented Spanish transcript with `¿…?`, then a **Supertonic Spanish voice** — not eSpeak | **7–11 s** to transcript `PROJECTED` |
| 5 | **French (CPU)** | "Quelle est la capitale de la France ?" | Accented French transcript, **Supertonic French voice** | **7–11 s** `PROJECTED` |
| 6 | Italian | anything | Falls through to the LFM CPU path, eSpeak voice. **Deliberate** — Italian was not wired | ~1 s |

Failure signatures, so you can tell a bug from the design:

- **"Spanish ASR is unavailable on the phone."** → the Parakeet files are missing or the
  companion is running an older APK. Re-run §3.
- **"Spanish ASR did not return reliable Latin text."** → the recognizer returned
  non-Latin output. Speak again, longer.
- **"Auto language is ambiguous…"** → correct behaviour. Auto never routes to ES/FR; pick
  the language explicitly.
- **A robotic Spanish voice** → Supertonic did not load and eSpeak took over. Check
  `candidates.json` actually contains `supertonic3_es_s5` with `auto_priority` above zero.
- **Silence with the transcript present** → every PCM chunk was dropped by `PcmGate`.
  This did not happen once in 69 host runs; if it happens on the phone, capture
  `last-parakeet.stderr` via `collect_esfr.sh` before doing anything else.

One more check that costs nothing and is worth having on tape:

```bash
adb -s "$SERIAL" shell dumpsys package ai.liquid.lfmdemo.runtime | grep -E 'versionCode|versionName'
```

## 6. Rollback

Ordered cheapest-first. Each step is independent; you rarely need more than the first.

1. **Disable ES/FR ASR, keep everything else** — the overlay is purely additive:

   ```bash
   $ESFR/rollback_esfr.sh
   ```

   Removes four Parakeet files from companion-private storage, then *asserts* the
   SenseVoice and Zipformer assets are still there. `parakeetArtifactsReady()` goes false,
   Spanish and French fail closed with a clear message, and EN/ZH/JA/KO/RU are untouched.
   No uninstall, no data clear. Reopen LFM Audio afterwards.

2. **Also revert the TTS catalog** — `$ESFR/rollback_esfr.sh --also-tts` prints the exact
   `install_main_app_tts_bundle.sh --manifest-only` command against your previous
   `tts-eval` tree. Metadata only; Spanish and French TTS return to eSpeak.

3. **Revert the source and rebuild** — if the *app* misbehaves rather than the route:

   ```bash
   git revert --no-edit <the two Lane F commits>
   scripts/build_android_apk.sh
   scripts/install_native_phone_demo.sh --apk android-app/app/build/outputs/apk/debug/app-debug.apk \
     --model-dir "$LFM_DEMO_WORK_ROOT/models/lfm25-audio-q4"
   scripts/install_app_owned_runtime.sh --serial "$SERIAL"
   ```

   `adb install -r` preserves package data, so nothing has to be re-pushed.

4. **Last resort — the historical APK.** `lfm-audio-demo-0.4.13-expressive-lfm-debug.apk`
   is the only retained artifact. It is a *single* app that predates the runtime companion:
   installing it gives up the app-UID ASR/Qwen architecture and every language except the
   LFM English path. Verify before use:

   ```bash
   shasum -a 256 -c android-app/releases/lfm-audio-demo-0.4.13-expressive-lfm-debug.apk.sha256
   ```

   Treat this as abandoning the demo, not as restoring it.

## 7. What to film

Shoot in this order. Airplane mode on, visible, from the first frame.

1. **The claim, in one shot.** Airplane mode in the status bar, then Settings → Apps →
   `LFM Audio` and `LFM Offline Runtime`, both installed. Nothing else needed to prove
   "offline".
2. **A fast language first.** Turn 1 or 3 from §5, uncut, so the audience sees the normal
   latency before they see the slow one.
3. **Spanish, uncut, with the wait in shot.** Tap, speak, wait, transcript appears, voice
   answers. Do not cut the pause out — the honest version of this demo is "it takes about
   ten seconds on the CPU", and a cut here is the one thing that would make the claim
   false. If the wait is unusable for the edit, cut the *shot*, not the *seconds*.
4. **French, same treatment.** Short prompt.
5. **The version card.** ES and FR are the two languages the product had no phone route
   for at all; that is the point of the sequence, and it is worth a caption.

Do **not** film or imply:

- any claim that Spanish or French run on the NPU — they run on the CPU, and the app's own
  telemetry says so (`npu_gate: "blocked"`);
- the physical unplug claim — it is still open (`docs/ANDROID_DEPLOYMENT.md:497`);
- Italian working — it falls through to eSpeak on purpose.

## 8. After the session

```bash
$ESFR/collect_esfr.sh /path/to/evidence
```

Read-only. Pulls the last runner stdout/stderr for all three backends, the installed
payload manifest, process/UID rows for both packages, the companion's ASR model tree, and
package versions. Add the two round-trip times from §3 — those are the first real phone
numbers for this route, and they are what turns F2's `PROJECTED` band into a measurement.
