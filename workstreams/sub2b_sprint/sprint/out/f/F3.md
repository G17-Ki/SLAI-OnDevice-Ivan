# F3 — ES/FR TTS through Supertonic

## Result

**69/69 synthesis runs passed both waveform gates. Zero chunks were dropped. The phone
gains zero model bytes.** `HOST`.

Spanish and French are now two more language routes over the *same* Supertonic 3 INT8
graphs the phone already runs for Russian, Japanese and Korean. Nothing is downloaded to
the device, nothing is reloaded when the language changes, and the engine's own runtime
safety gate was used as the pass/fail criterion rather than a gate invented for this lane.

## 1. Why this is a configuration change, not an integration

`scripts/tts_research_20260726/stage_device_bundle.py:100-117` emits the same seven file
paths for every Supertonic language. `CandidateRegistry.sharesModelWith()`
(`tts/CandidateRegistry.kt:55-58`) treats two candidates as one resident graph when
`engine`, `numThreads` and the whole `files` map are equal, and
`SherpaTtsEngine.canReuseModel()` / `selectCandidate()` (`tts/SherpaTtsEngine.kt:117-129`)
then swap language without allocating a second `OfflineTts`. The language itself travels
in `GenerationConfig.extra["lang"]` (`:253-261`), one string per request.

So the entire ES/FR TTS change is:

| # | File | Change |
|---|---|---|
| 1 | `stage_device_bundle.py:78` | `language_labels` gains `"es": "ES", "fr": "FR"` |
| 2 | `stage_device_bundle.py:86-99` | host notes for the two new rows, sourced from Lane D and this lane |
| 3 | `stage_device_bundle.py:219-221` | `supertonic(5, "es")`, `supertonic(5, "fr")` |
| 4 | `stage_device_bundle.py:248-258` | ES/FR `PHRASES` for the on-device phrase picker |
| 5 | `tts/CandidateRegistry.kt:135-146` | `supertonic3_es_s5` / `supertonic3_fr_s5` in the default `auto_priority` whitelist |
| 6 | `NativeAudioBridge.java:263-265` | the user-visible routing description now names Spanish and French |

Two host gates were **extended, not relaxed**, so the shared-graph property is now
enforced rather than assumed:

- `scripts/test_tts_device_bundle_metadata.py:26-45` — five expected Supertonic ids, all
  five languages, `es`/`fr` present in `PHRASES`.
- `scripts/test_tts_candidate_registry_contract.py:251-273` — all five routes must reduce
  to **one** `model_signature`, must declare `extra.lang`, must have `auto_priority > 0`
  and `num_steps == 5`.

### The one thing I checked before trusting any of it

`OfflineTtsSupertonicModelConfig` has seven `String` fields and **no** `dataDir`. I
verified that with `javap` against `~/.cache/lmf-demo/sherpa-aar/sherpa-onnx-1.13.4.aar`,
the exact AAR the app links. The sherpa-onnx JNI binary contains the strings `has_espeak`
and `use espeak for %s`, so some Supertonic languages could in principle require
espeak-ng data that this config cannot supply. The shipped
`sherpa-onnx-supertonic-3-tts-int8-2026-05-11/tts.json` declares no per-language espeak
requirement, its bundled `README.md:243-244` lists `es` Spanish and `fr` French among 31
supported codes (`VENDOR`), Lane D synthesized both languages from the identical file set
(`out/d/D3.json`), and this lane synthesized 69 more runs with no extra data directory.
That is enough to ship the configuration; it is not a licence to assume every one of the
31 codes behaves the same way.

## 2. The gates

Every generated chunk was scored **twice**, at the point the app scores it and again over
the whole waveform.

**PCM_GATE** — a faithful port of `tts/PcmGate.kt:20-89`, which is what actually stands
between sherpa-onnx and `AudioTrack` on the phone. Fails on: any non-finite sample,
`rms < 0.005`, clip fraction `> 0.001` at `|x| >= 0.999`, or `|dc| > 0.10`. In the app a
failing chunk is dropped (`SherpaTtsEngine.kt:271-275`) and an utterance whose chunks are
*all* dropped raises `all_chunks_rejected_invalid_pcm` (`:324-327`). Both conditions were
checked.

**D3_GATE** — Lane D's exact short-input gate, copied from `out/d/D3.json` `gate`: finite,
non-empty, RMS above −50 dBFS, duration within [0.15, 30] s, and no contiguous run above
−0.1 dBFS longer than 5 ms.

A run passes only if every chunk passes PCM_GATE, no chunk was dropped, and the joined
waveform passes both gates.

## 4. What the numbers say

| | Spanish | French |
|---|---|---|
| runs | 36 | 33 |
| passed both gates | **36** | **33** |
| chunks dropped by PcmGate | **0** | **0** |
| shortest output | 1.317 s | 1.301 s |
| longest output | 5.402 s | 6.457 s |
| lowest whole-waveform RMS | 0.0495 | 0.0479 |

Two things are worth pulling out.

**The short-input failure mode that killed Piper cannot occur here.** Piper DaveFX ES
returned 0.081 s for `A`; Supertonic returned **1.317 s** for the same text. Every
single-character input produced roughly 1.3 s of audio. Supertonic's duration predictor
has a floor well above the 0.15 s gate, so the entire class of "too short to be audio"
failures is absent by construction, not by luck.

**The lowest RMS observed anywhere was 0.0479 — roughly ten times the 0.005 floor.** There
was no marginal case. Nothing was close to failing.

### Latency: I measured it, and the measurement is not usable

`sherpa-onnx` emitted **exactly one callback chunk per utterance** at these text lengths.
`first_chunk_ms` therefore equals whole-utterance synthesis time: the Supertonic path did
not stream here. That is a structural finding and it does not depend on timing.

The timings themselves are junk, and saying so is more useful than dressing them up.
Observed real-time factor across all recorded ES/FR runs spans **0.75 to 26.5** — a 35×
spread on identical inputs and identical configuration. The cause is the machine: this Mac
carried load average 29–53 on eight cores throughout the measurement window, with
unrelated applications holding 40–90% CPU, and a rerun of the same command an hour later
differed by more than 7×.

`F3.json` therefore records `host_timing_quality.usable: false` and classes the latency
evidence **`UNKNOWN`**, not `HOST`, because `HOST` would imply the number means something.
**There is no ES/FR TTS latency figure in this lane and none should be quoted from it.**

None of this touches the verdict. Whether a waveform is finite, non-silent, unclipped and
of plausible duration is arithmetic over samples; it does not care how busy the CPU was.
69/69 stands, and so does zero dropped chunks.

The recorded phone figures for the same engine and step count are much faster —
RU/JA/KO final chunks at 290/584/390 ms (`PRIOR`,
`reports/android_phone/model_sweep_20260729/PRIORITIZED_MODEL_SWEEP.md:115`) and
"RU resolved to Supertonic s5: 508 ms first synthesis chunk" (`PRIOR`). **I am not going
to reconcile those with my host numbers.** They measure a different point (final chunk vs
whole utterance), different text, and a different machine. The honest statement is: the
phone has already produced fast Supertonic audio for three languages through this exact
code path, ES/FR use the same graphs, and this lane produced no phone timing at all.

For the same reason I draw no thread conclusion. Both 2 and 4 threads passed 69/69;
`device_threads()` already gives Supertonic 4 on the NX809J, and whether that is the right
value must be measured on the phone rather than inferred from this.

## 5. Fixtures produced

Ten reference renders (five per language), each written in the app's canonical
16 kHz mono PCM16 contract so the same file can be pushed, played, or fed back through
ASR. Native Supertonic output is 44.1 kHz; these are resampled once for storage. Hashes
are in `artifact_registry.json` and `artifacts/nubia_esfr_bundle/manifest/esfr_payload.psv`.

They exist so that after the demo you can A/B what the phone produced against what the
host produced from identical inputs. They are not a quality claim.

## 6. What this does not establish

- **Not intelligibility, naturalness, or language correctness.** A finite, non-silent,
  unclipped waveform of plausible duration can still be wrong in every way that matters to
  a listener. Lane D's D1 ranked Supertonic ES and FR as `UNSTABLE — no rank`.
- **Not a phone measurement.** No phone was connected.
- **Not licence clearance.** Supertonic 3 is OpenRAIL-M; use restrictions follow both the
  model and the audio it generates. See `out/a/licences/supertonic-3-openrail-m_2026-08-02.txt`.
- **Not the other 26 languages** the model card lists. Two were tested.
