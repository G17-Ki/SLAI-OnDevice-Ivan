## 1. How ASR is routed per language

Two independent layers decide. Both must be changed for ES/FR.

```

                 "message":"Use auto, qnn-auto, en, zh, ja, ko, or ru"}   (166-171)
```

**ES and FR hit line 167 and are refused before any model runs.**

### 1c. The input contract every ES/FR route must satisfy

`AsrHttpServer.java:494-505` accepts a WAV only if it is `RIFF`/`WAVE`/`fmt `/`data` at
offsets 0/8/12/36, PCM format `1`, **mono**, **16,000 Hz**, **16 bit**, and
`u32@40 == length - 44`. That is a bare 44-byte header with no extra chunks. The client
enforces the same shape when it segments (`index.html:1053-1054`,
`MAX_COMPANION_SEGMENT_SECONDS = 9.5`).

Note for F4: the Parakeet vendor demo WAVs are **22,050 Hz / 24,000 Hz** and are rejected
by this gate as shipped. Lane F resamples them once, offline, to the canonical layout.

| 7 | `NativeAudioBridge.java:263-265` | Update the user-visible automatic-routing description |

Two things that deliberately do **not** change:

- **No new QNN provider.** The Parakeet SM8850 contexts Lane E verified embed
  `2.40.0.251030114326_189385` (`out/e/E3.json:94`) while the programme pins
  `2.45.0.260326154327` (`out/e/E5.json`). `runtime-companion` already hosts a QNN 2.40
  SenseVoice provider. Loading a second provider in that process is exactly the failure
  the four probe packages exist to avoid. F2 records the decision.
- **No `data_dir`.** `OfflineTtsSupertonicModelConfig` has no espeak field (verified by
  `javap` against `sherpa-onnx-1.13.4.aar`: seven `String` fields, no `dataDir`), and the
  shipped `tts.json` declares no per-language espeak requirement for ES/FR. ES/FR reuse
  the resident RU/JA/KO graph byte-for-byte.

## 5. What "one probe app" taught me

`android-app/supertonic-probe/` is the smallest of the four and is the template for
option (a) in F2:

- `src/main/AndroidManifest.xml:12-14` — `<uses-native-library android:name="libcdsprpc.so">`,
  the FastRPC declaration without which `deviceCreate()` fails with QNN 14001
  (also in `runtime-companion/src/main/AndroidManifest.xml:26-28`).
- `SupertonicQnnProbe.java:48-53` — `ADSP_LIBRARY_PATH` and `LD_LIBRARY_PATH` are prepended
  to point at *this package's* `nativeLibraryDir`, then the QNN libraries are `System.load`ed
  in stub-before-backend order. A package's QNN version is decided by its own APK payload.
- `:59-65` — hard assertions on the ONNX Runtime version and on `OrtProvider.QNN` presence.
- `:76` — `session.disable_cpu_ep_fallback = 1`, so a silent CPU fallback cannot be
  mistaken for NPU execution.
- The manifest grants **no** `INTERNET`, `RECORD_AUDIO`, or storage permission.

That is the whole isolation recipe: a separate package, its own native library directory,
its own QNN version, no silent fallback. It is four files plus a Gradle module.
