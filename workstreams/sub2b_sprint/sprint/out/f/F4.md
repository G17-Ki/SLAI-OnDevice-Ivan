# F4 — The staged ES/FR bundle

`artifacts/nubia_esfr_bundle/` · registry `artifact_registry.json` · **no phone was

## What it is

An **overlay** on the two-package deployment that `docs/ANDROID_DEPLOYMENT.md` already
installs. It adds Spanish and French and changes nothing else. It installs no APK, clears
no package data, touches no SenseVoice / Zipformer / Qwen / LFM asset, and refuses to run
unless both `ai.liquid.lfmdemo` and `ai.liquid.lfmdemo.runtime` are already present.

## Extending Lane E rather than starting over

Lane E's `out/e/artifacts/nubia_bundle` is built around a generic `apks/harness.apk` that
was never produced, so `require_runner()` blocks every path with
`BLOCKED_APP_RUNNER_MISSING`. That marker is true of Lane E's bundle and false of this
repository. Lane F keeps Lane E's discipline and drops the parts that have nothing to
govern:

| Lane E behaviour | Lane F |
|---|---|
| exactly one authorized NX809J / SM8850 / arm64-v8a target | kept verbatim |
| zero adb forwards, asserted before **and** after | kept, plus a scoped exception (below) |
| byte size + SHA-256 on the host, again after import | kept, and split into two passes |
| `run-as` UID must equal the package UID, never root or shell | kept |
| atomic `.incoming` → `mv` placement | kept |
| `require_runner()` blocks on a staged APK file | **replaced** by "both packages must already be installed, one unsplit APK each" — a stronger precondition |
| QAIRT 2.45 pin, `npu_pairs.psv`, context/runtime matching | **removed**: a CPU-only route has no pair to match |
| — | **added**: `assert_no_npu_payload()` refuses any row that looks like a QNN context or Qualcomm runtime object, exit `24` |

`lib/common.sh` states each divergence at the line where it happens, so the next reader
does not have to diff two bundles to find them.

### The one forward, and why it is not a loophole

`verify_esfr.sh` opens a temporary loopback forward, posts two fixtures, removes it, and
then calls `assert_no_adb_forwards()` again. That is exactly what
`docs/ANDROID_DEPLOYMENT.md` step 4 already does for the accepted five languages. The
forward exists only so the **host** can drive acceptance; on-device inference never uses
it, and `install_esfr.sh`, `rollback_esfr.sh` and `collect_esfr.sh` never create one.

Every payload file is verified twice on the way in — once against the manifest on the
host, once after import, as a **separate pass** so a mid-run failure cannot leave a
half-verified install looking complete.

## What the safety suite actually proves

`tests/smoke.sh` runs 20 cases against a read-only `adb` double. All pass; no real `adb`
binary is invoked. `shellcheck -x -s sh` is clean over all seven shell files.

Refusals proven: zero devices · two devices · an unauthorized device · a non-SM8850
device · a pre-existing adb forward · unreadable forward state · the companion not
installed · the main app not installed · a split APK · `run-as` resolving to root ·
`run-as` denied — for `install`, `verify`, `rollback` and `collect` as applicable.

Two of the twenty matter more than the rest. A payload manifest with a planted
`qnn_context` row and one with a planted `libQnnHtp.so` row are both rejected with exit
`24` **before any device is contacted**. The CPU-only guarantee is enforced by the script,
not by review.

## The registry

`artifact_registry.json`, 26 rows. Every row carries `source_url`, `revision`,
`expected_bytes`, `local_sha256`, `checksum_status`, `licence`, `licence_source_url`,
`destination`, `artifact_type`, `required_runtime`, `required_runtime_version`,
`npu_claim: false`, and `readiness`.

- **Parakeet** — the archive plus its four extracted members. Archive
  487,170,055 bytes, SHA-256
  `5793d0fd397c5778d2cf2126994d58e9d56b1be7c04d13c7a15bb1b4eafb16bf`, verified locally
  and then deleted. CC-BY-4.0 parent model; the release payload carries no licence file,
  so attribution must accompany redistribution.
- **Supertonic** — all nine files of the resident graph set, hashed, marked
  `RESIDENT_REUSED_BY_ES_FR_ROUTES` because this bundle does **not** re-push them. The
  archive pin matches `scripts/supertonic3/download_model.sh:12` exactly
  (`82fa96f9…f432c427`), which is an independent confirmation of the repo's own pin.
- **Fixtures** — twelve WAVs. The two ASR fixtures are the vendor demo clips resampled
  once to the canonical contract; the ten TTS fixtures are this lane's Supertonic renders.
  The TTS fixtures inherit OpenRAIL-M use restrictions from the model that produced them,
  and the registry says so.

Four `unmet_dependencies` are recorded explicitly: phone execution, ES/FR accuracy,
listening acceptance, and the persistent-recognizer follow-up from F2 §6.

## Storage

Lane F's git-ignored artifacts total roughly **781 MiB** against the 3 GB cap. Both source
archives (487 MB + 129 MB) were deleted after verified extraction. No weight, WAV, APK,
`.so` or Qualcomm object is committed; the control plane — scripts, manifests, registry —
is, matching how Lane E committed its own.

## What it does not prove

It was never run against a phone. `install_esfr.sh`, `verify_esfr.sh`,
`rollback_esfr.sh` and `collect_esfr.sh` have been proven to *refuse* correctly and to be
syntactically and statically clean; they have not been proven to *succeed*. The first real
evidence for this route will be the two round-trip times `verify_esfr.sh` prints.
