1项目一句话

在一台零售高通手机上跑通了一个完全离线（飞行模式可用）的多语言语音助手闭环： 用户说话 → VAD 判停 → ASR（NPU/CPU）→ LLM 流式生成 → TTS 流式合成 → 扬声器。 不依赖网络、不依赖 ADB，推理进程全部归应用自有 UID。

项目核心价值是「证明可行性 + 可复现的工程底座」，不是一个可直接发布的成品。当前是 debuggable 研究构建，未做生产加固。

2.2 必须说清楚的证据边界

  • 当前源码 ≠ 已验收安装对。已验收的是手机上安装的 APK 对（主 a24e203a… / runtime 33bf0d6d…）。当前源码更新，且已关闭 LFM 运行时（LFM_RUNTIME_ENABLED=false，无代码启动 LfmService）。README 的 "Current phone stack" 描述的是手机上那对旧 APK。当前源码要继承其时延/离线声明，必须重跑设备验收。
  • AI Hub QRD 数字是同芯片组参考，不是零售手机时延，更不能外推到眼镜（AR1）。
  • 物理拔 USB 线仍是操作员门槛，未完成。现有证据是「宿主 ADB 关闭 70 s 进程存活」，不是「拔线后对话」。
  • 法/意/西/德的 eSpeak 标签不等于这些语言有健壮的端到端路线。
  • 宿主测试不能证明手机时延、HTP 执行、声学质量、热稳定、拔线存活。

2.4 模型质量诚实声明

  • Qwen2.5-1.5B 在小扫描（28 题）中 FR/JA/KO 存在事实错误 → 不能作为「通用多语言模型」宣传；中文/俄语小集合通过。
  • SenseVoice 中文在 3 片段诊断上 CER 33%（小样本冒烟，非发表级基准）。
  • Matcha 中文音色继承非商业训练语料限制，再分发/商用前必须审 TTS 报告。
  • ASR 固定 10 秒图（短音频零填充，长音频切 9.5 s 段）；单句 15 s 上限（手动录音 30 s）。
  • 除 SenseVoice EN/ZH/JA/KO 在 NPU 外，全部推理在 CPU；Qwen 进程 PSS ≈1.95 GB。

320 样本（20 ms）帧喂入确定性状态机 IDLE → LISTENING → SPEECH → HANGOVER → ENDPOINT。

噪声底只在非脉冲非活跃帧学习，确认语音后冻结；助手播放期间 VAD 整体屏蔽（barge-in=DISABLED，能量门无法可靠区分用户与合成音）。设计取舍：宁可多等 420 ms，不截断尾音、不误触发。

2) ASR（runtime APK，127.0.0.1:6010）

  • 契约：POST /asr?language=…，规范 16 kHz mono WAV（≤10 s），零填充到固定 10 秒图（320,044 字节）后调 QNN。
  • 路由：en/zh/ja/ko → SenseVoiceSmall INT8 NPU（RTF≈0.009，返回文本 + 语言标签 <|ja|> 等）；ru → Zipformer INT8 CPU；代码中另存 parakeet_v3_cpu 备用路线。
  • 持久 runner：ASR 引擎常驻子进程（stdin-json 协议）；切换语言路线先 quit 旧进程再分配，避免双份内存。
  • 执行感知健康：artifacts_ready（文件在盘）/ execution_verified（当前进程出过非空转录）/ ready + UID 归属证据 + QNN 日志须含 Initializing HtpProvider。
  • 串行代价（已明确记录）：对话模式先完成 ASR 再启动 LLM，音频被处理两遍——这是 ~2 s 预算里可优化的部分。

3) LLM（runtime APK，:6020，CPU）

  • 官方 llama.cpp b10083 server 加载 Qwen2.5-1.5B-Instruct Q4_K_M。
  • 参数：ctx 2048 / 1 slot / 4 线程 / batch 128 / micro-batch 64 / 0 GPU 层。
  • 接口：OpenAI 兼容 POST /v1/chat/completions（流式）+ /health + /v1/models；只对 Qwen3 发 thinking 控制字段（能力探测）。
  • 手机实测（28 题短问）：首 token 304/475 ms；首句可读文本 672/1,253 ms；整句 707/1,601 ms；84.4/33.2 tok/s；PSS ≈1.95 GB。
  • RuntimeService 负责启动、监控、崩溃重启该子进程，持 active-client 非引用计数 wakelock。

4) TTS（主 APK，语言感知路由，流式）

  • 候选不在 APK 里：CandidateRegistry 从外部 bundle 的 candidates.json 读取——换音色/加候选不重编译 APK（刻意设计）。
  • 自动路由：zh → matcha_zh_baker；ru/ja/ko → supertonic3 五步；其余 → eSpeak 离线兜底。手动 pin 文件不全必须显式报错，不许静默落错模型。
  • 流式链路：LLM 吐出第一句可读分句（标点/长度 flush）即提交 TTS → 每块过 PcmGate 安全门（非有限 PCM / 近静音 / 削波 / DC 偏移 → 丢块不播噪声）→ 有序播放队列（播放前/后取消、多块排序）。
  • 空闲预载：按当前 locale 预热线图，独立 token，绝不推进在途轮次。
  • 实测：Matcha 中文 end-to-speaker 118 ms；Supertonic 首块 RU 496 / JA 577 / KO 395 ms，全部零掉块。

5) 播放与半双工

播放期间 VAD 屏蔽 + 噪声底冻结（防自激）；规划播放 cushion 140 ms。实测完整轮 27 块 PCM、零 underflow、零质量告警。

5用另一个级联方案替换某个模型：最小最保险的改动方式

5.1 核心原则：在「契约缝」上换，不在流程里换

这套架构最大的资产：四个模型角色之间只有三条稳定的回环 HTTP 契约。只要新方案在同一端口、同一套协议后面，主应用（UI / VAD / 编排 / TTS / 播放 / 遥测）一行代码都不用改，替换边界被压缩到 runtime companion 内部。
契约端口协议
ASR6010POST /asr → candidates[i].result.text（16 kHz WAV in）
LLM6020OpenAI 兼容 /v1/chat/completions（流式）+ /health + /v1/models
LFM8080llama.cpp 风格（当前停用）

5.2 放置位置：必须进 runtime companion APK

  • 不能在 adb shell 里跑（adbd cgroup 生命周期缺陷，已被架构淘汰）；
  • 不能走云端（离线是硬需求）；
  • companion 是现成的「模型运行时」边界：子进程启动/监控/重启、模型私有存储、健康端点、UID 归属验证都在那里；
  • 若新方案本身是多模型级联（如小模型意图路由 + 大模型生成），实现为 companion 内新子进程（或 llama.cpp 多模型/多 slot），RuntimeService 按现有模式纳入生命周期管理，对外仍只暴露一个 :6020。

5.3 最小 diff 食谱（以替换 LLM 为例，难度最低的一段）

#改什么文件
1新模型 pin（repo / revision / filename / 字节数 / SHA-256）reports/.../model_candidate_followup/candidate_manifest.json
2server 启动命令（模型路径、别名、ctx、线程、batch）；保持 /health、/v1/models 语义runtime-companion/.../RuntimeService.java
3模型文件校验 + 身份断言（/v1/models 返回 id）+ 真实 fixturescripts/install_app_owned_runtime.sh
4源一致性断言（新启动参数、无禁用 flag）scripts/test_runtime_companion_source.py
5主应用零改动

预算检查：首 token 守住 672 ms 量级（否则吃掉 2 s 总预算）；PSS 预算（现 ~2 GB）；响应长度上限在主应用侧，需同步。

要换的段难度关键点

5.6 保险清单（明确不做的事）

  • 不动 VAD、ASR 输入契约（16 kHz / 10 s 零填充）、TTS bundle 结构、端口、签名权限——除非新方案本身改变输入形态。
  • 不在生产包上直接试错：用 .dev 隔离；签名不一致的安装会失败而非损坏（天然保险）。
  • 不接受「文件在 = 就绪」：沿用 execution_verified 语义。
  • 先量时延再谈质量：流水线串行，新段每慢 100 ms 直接吃掉 2 s 预算。
  • 许可同级审查：新模型 license 与 Matcha 语料限制一样进 THIRD_PARTY_NOTICES 与发布说明。
  • 双 pair 不能同时运行（固定回环端口 8765/6010/6020/8080）：切换时 force-stop 旧 pair（不是卸载）。
