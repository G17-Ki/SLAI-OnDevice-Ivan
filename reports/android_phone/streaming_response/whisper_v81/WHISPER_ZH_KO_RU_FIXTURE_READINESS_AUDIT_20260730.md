# Whisper ZH/KO/RU semantic-fixture readiness audit

Date: 2026-07-30

## Scope and safety

This was a host-only audit. It did not invoke ADB, build or install an APK, run
model inference, access the network, or modify any existing frontend/semantic
trust root. Frontend calculations used one Torch thread and the already-pinned
QAI preprocessing recipe. The resulting ZH/KO/RU tensors are provisional audit
outputs, not accepted assets or trust roots.

## Result

The repository already has authenticated, canonical 16 kHz mono PCM16 WAVs and
reference text for Chinese, Korean, and Russian. The Whisper decoder policy also
already has the correct language-token IDs and the semantic verifier already
recognizes all three languages.

The remaining blockers are packaging and contract work:

- ZH/KO/RU QAI frontend goldens are not present in the canonical frontend
  audit/bundle.
- The Android frontend implementation, Gradle build restriction, host tests,
  and device verifier are hard-coded to exactly `en` and `ja`.
- There are no independent whole-APK/spec trust roots for ZH, KO, or RU.

There is no frontend-numerics blocker. Provisional QAI goldens for all three
languages pass the current host native bound: maximum UINT16 delta `1`, no more
than `240` differing values, and differing fraction no more than `0.001`.

## Tokenizer and detokenizer requirements

No additional phone-resident tokenizer file is required. The existing release
payload already pins:

- `multilingual.tiktoken`: 816,730 bytes,
  SHA-256 `b34b360dbb493e781e479794586d661700670d65564001f23024971d1f2fa126`.
- Qualcomm VoiceAI `vocab.bin`: 357,313 bytes,
  SHA-256 `0ba87984671b92e03b56b84ce9b217020663f6a269b5a9800901391430b79c4b`.
- Exactly 50,257 mergeable/base entries, with raw-NUL token 188 and empty token
  50,256.

The VoiceAI vocabulary round-tripped all references byte-for-byte when token
bytes were concatenated before a single UTF-8 decode:

- ZH: `[27908, 9254, 5975, 17174, 11249, 222, 47446, 30312, 10115, 235, 8861, 26668, 31375, 1543]`
- KO: `[42334, 9143, 7785, 2785, 23455, 1098, 20879, 4215, 28517, 30]`
- RU: `[11179, 2019, 4218, 43862, 11384, 1631, 3752, 1000, 38842, 387, 13]`

All IDs are below EOT (`50257`), so the existing generated-token domain admits
them. The existing language-token IDs are also correct:

- ZH `50260`, prompt `[50258, 50260, 50359, 50363]`
- RU `50263`, prompt `[50258, 50263, 50359, 50363]`
- KO `50264`, prompt `[50258, 50264, 50359, 50363]`

Do not require generated IDs to equal the reference tokenizer IDs: alternate
base-token segmentations can decode to the same valid transcript. Require text
accuracy, and require generated-ID determinism only across repeated runs of the
same APK.

Recommended detokenizer hardening before multilingual promotion:

- Make `VocabDecoder` use a strict UTF-8 `CharsetDecoder` with malformed and
  unmappable input set to `REPORT`, instead of silently inserting U+FFFD.
- Have the semantic verifier reject U+FFFD and NUL/control characters in the
  final candidate transcript.
- Add host regression vectors for the ZH/KO/RU token lists above. The current
  byte-concatenate-then-decode design is otherwise correct for split multi-byte
  tokens.

## Exact implementation change map

The safest implementation is a new multilang frontend-v2 lane. Do not edit the
accepted EN or JA semantic specs. Existing APK trust roots remain valid, while
any rebuild from generalized source must receive a new whole-APK hash/spec.

1. `scripts/compare_whisper_native_frontend.py`

   - Add `zh`, `ko`, and `ru` entries to `FIXTURES` using the WAV/PCM and
     float/quantized hashes above.
   - Generate and compare reference outputs for all five languages in a stable
     order.
   - Keep the existing one-thread/lightweight host policy when regenerating.

2. Add a versioned stager, preferably
   `scripts/stage_whisper_android_frontend_assets_multilang.py`, rather than
   changing the v1 stager pinned by existing trust roots.

   - Use a new asset prefix such as `whisper_frontend/v2` and a new gate ID.
   - Stage five WAVs, five UINT16 goldens, the Hann table, and the mel table:
     12 authenticated assets total.
   - Pin the ZH/KO/RU identities above and generate a fresh canonical manifest
     SHA-256. Do not copy the current v1 manifest hash into Gradle.

3. `android-app/whisper-probe/build.gradle`

   - Extend the exact language allow-list from `['en', 'ja']` to
     `['en', 'zh', 'ru', 'ko', 'ja']`.
   - Point frontend verification at the v2 manifest path/hash.
   - Preserve JDK 17, NDK `27.0.12077973`, and no more than two Gradle workers.

4. `android-app/whisper-probe/src/main/java/ai/liquid/lfmdemo/whisperprobe/WhisperFrontendProbe.java`

   - Replace the two fixture constants/result fields with a deterministic
     fixture registry and `Map<String, byte[]>` outputs.
   - Add ZH/KO/RU WAV frame counts and provisional golden identities.
   - Make manifest asset verification, report fixture objects, timing objects,
     aggregate timing, and `featuresForLanguage` data-driven.
   - Retain English features for the unchanged four-step synthetic compatibility
     probe.

5. `android-app/whisper-probe/src/main/java/ai/liquid/lfmdemo/whisperprobe/ProbeActivity.java`

   - Parse the build-pinned semantic language before frontend execution.
   - Replace direct `englishFeatures` access with
     `featuresForLanguage("en")`.
   - Update EN/JA-only status text.
   - For lower candidate latency, compute only EN plus the selected semantic
     language in semantic builds; use a separate verify-all frontend build/run
     to execute all five fixtures. Existing phone results show about 32 ms per
     frontend fixture, so always computing five would add roughly 96 ms over
     the current EN+JA path.

6. No functional language changes are required in
   `WhisperDecodePolicy.java` or `WhisperQnnProbe.java`; both are already generic
   for ZH/RU/KO. Add only the strict detokenizer hardening described above.

7. Add a v2 whole-APK verifier (or make the current verifier explicitly
   profile-aware) without invalidating v1 defaults.

   - In `verify_whisper_android_frontend_apk.py`, the manifest path at line 162
     is hard-coded to `whisper_frontend/v1/manifest.json`.
   - In `verify_whisper_android_frontend_device.py`, fixture sets, timing keys,
     and aggregate sums at lines 398-435 are hard-coded to `en`/`ja`. Derive
     them from `frontend_contract['fixtures']` and require timing keys to equal
     `fixture_names | {'aggregate'}`.
   - `run_whisper_android_frontend_device_probe.py` is otherwise language-agnostic.

8. Update focused host tests:

   - `scripts/test_whisper_android_frontend.py`: expect 12 assets and run the
     native comparator for all five languages.
   - `scripts/test_verify_whisper_android_frontend_device.py`: construct fixture
     and timing dictionaries dynamically.
   - `scripts/test_whisper_ort_qnn_probe_source.py`: update the Gradle allow-list
     assertion and replace EN/JA-specific frontend-field assertions.
   - `scripts/test_verify_whisper_semantic_device.py`: add ZH, KO, and RU
     contract/candidate cases plus invalid UTF-8 replacement/control rejection.
   - Keep existing EN/JA tests as immutable regression controls.

9. Create new specs only after the final APK exists:

   - one v2 frontend whole-APK trust root;
   - separate ZH, KO, and RU semantic specs/APK hashes;
   - two isolated device runs per language, with the probe process stopped after
     each lane and accepted package hashes checked before/after.

## Proposed language-specific semantic gates

These fit the current `semantic_decode_overlay` schema and should be declared
before the first device run.

| Language | Build flag | Reference metric gate | Why |
|---|---|---|---|
| ZH | `WHISPER_SEMANTIC_DECODE_ENABLED=true;WHISPER_SEMANTIC_LANGUAGE=zh` | `max_wer=1.0`, `max_cer=0.20` | Current normalization treats the unspaced sentence as one word, so CER is authoritative; 0.20 permits at most 2 edits over 12 normalized characters. |
| KO | `WHISPER_SEMANTIC_DECODE_ENABLED=true;WHISPER_SEMANTIC_LANGUAGE=ko` | `max_wer=0.34`, `max_cer=0.20` | Allows at most 1 edit over 3 words and 2 edits over 12 normalized Hangul characters. |
| RU | `WHISPER_SEMANTIC_DECODE_ENABLED=true;WHISPER_SEMANTIC_LANGUAGE=ru` | `max_wer=0.25`, `max_cer=0.10` | Allows at most 1 edit over 4 words and 2 edits over 22 normalized Cyrillic characters; existing host calibration produced WER 0.25/CER 0.0455. |

For all three languages also require:

- EOT reached, final generated ID exactly `50257`, no earlier EOT.
- At most 199 decoder calls and 196 generated IDs.
- Every generated ID in `0..50257`; controls/timestamps remain suppressed.
- Cumulative right-aligned UINT16 attention mask and the existing call/token
  invariant.
- `max_semantic_compute_ms=2500` for first-candidate compatibility with the EN
  and JA specs. Record the observed value; a later low-latency promotion gate
  should be tightened prospectively, not retroactively.
- Two device runs from the identical APK/spec with identical normalized
  transcript and generated-token sequence.
- No U+FFFD, NUL, or unexpected dominant script. Preserve semantic anchors:
  ZH `中文` and `北京`; KO `프랑스` and `수도`; RU `коротко` and `москве` after
  case folding.

The ZH gate intentionally evaluates Simplified Chinese. Traditional Chinese
should be a separate locale/reference policy rather than silently normalized
into this trust root.
